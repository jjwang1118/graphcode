# frontend 規格

前端的職責、資料流、視覺編碼、互動行為與硬性規則。

後端的實作決定見 [Backend.md](Backend.md)；檔案擺放見 [System_arch.md](System_arch.md)；進度見 [plan.md](plan.md)。

---

## 定位

| | |
|---|---|
| **做什麼** | 把後端回傳的 `{ nodes, edges, meta }` 畫成可探索的圖 |
| **不做什麼** | 不做任何圖的運算。篩選、循環偵測、鄰居查詢**全部由後端負責**——前端只換一個請求參數 |

「視圖 = 同一張圖的查詢條件」這條原則在前端的意思是：切換目錄樹／依賴圖不是換元件，是換 `edge_types` 這個欄位。

## 檔案與職責

| 檔案 | 負責 | 不該出現什麼 |
|---|---|---|
| `src/api/types.ts` | 與後端 pydantic 對應的型別 | 任何邏輯 |
| `src/api/client.ts` | `fetch` 封裝，唯一碰 HTTP 的地方 | 圖的知識 |
| `src/graph/transform.ts` | API 形狀 → Cytoscape elements、平行邊聚合 | React、DOM、cytoscape 的 import |
| `src/graph/style.ts` | 顏色、形狀、大小、狀態樣式 | 邏輯與資料 |
| `src/graph/layouts.ts` | 四種排版的參數 | 間距（見下方「間距」） |
| `src/graph/views.ts` | 三種視圖 → `edge_types` ＋ 預設排版 | 篩選的實作（那在後端） |
| `src/graph/levels.ts` | 層級選項、外部套件模式、層級 → 預設排版 | 收合的實作（那在後端） |
| `src/components/GraphCanvas.tsx` | 2D 畫布：Cytoscape 實例、互動、縮圖 | 樣式常數（都在 `style.ts`） |
| `src/components/Graph3D.tsx` | 3D 畫布：three.js 場景、互動 | 同上；另外不重算資料，吃的是同一份 `toElements()` |
| `src/components/DetailBox.tsx` | 釘住的細節框：顯示 ＋ 自己的關閉規則，兩個畫布共用 | 畫布或引擎的知識——它只收座標與 `ImportDetail[]` |
| `src/components/Sidebar.tsx` | 控制項與圖例 | 對 cytoscape 的直接操作 |
| `src/App.tsx` | 狀態與版面 | 上述任何一項的細節 |
| `src/index.css` | 全域底色與背景動畫 | 元件樣式（元件用 inline style） |

`transform.ts` 刻意**不 import cytoscape**：它是純函式，測試不用載入繪圖引擎，也不必等畫布存在就能寫。

## 資料流

```
使用者輸入路徑
      │
      ▼
client.analyze({ path, level, externals, edge_types? })   POST /api/analyze
      │  GraphDocument
      ▼
App 的 useState                          ← 唯一的資料來源
      │
      ├──→ GraphCanvas ── transform.toElements() ──→ cytoscape 實例（ref）
      └──→ Graph3D     ── transform.toElements() ──→ three.js 場景（ref）
```

React 只負責**餵資料**與**觸發排版**。兩個畫布的實例都不在 state 裡。

`toElements()` 是兩者共用的那一步——**這就是「換掉的只有畫布那一層」的實作依據**，見下方「畫布」。

## 畫布

**兩個畫布並存，sidebar 一個按鈕切換，預設 3D。** 3D 起初是 `experiment/3d` 上的實驗，目視驗收後暫定採用（plan 4.2），2D 留著。

| | 2D | 3D |
|---|---|---|
| 引擎 | Cytoscape | `3d-force-graph` 1.80 / three.js |
| 元件 | `GraphCanvas.tsx` | `Graph3D.tsx` |
| 實例 | ref | ref |
| 吃什麼 | `toElements(graph)` | **同一個** `toElements(graph)` |
| 排版 | 四種可選，見「排版」 | 只有力導向，持續在跑 |
| 間距滑桿 | 排完之後等比例縮放座標 | 改力導向的**理想邊長**（`24 × spacing`），排版自己鬆開 |
| 標籤 | Cytoscape 的 `label` | 球體上方的文字精靈（`SpriteText`），永遠面向鏡頭 |
| hover | 節點與相鄰邊變紫，其餘淡到 12% | 同樣的行為，但**顏色自己帶 alpha**（3D 沒有整體 opacity） |
| 點擊 | 選取 | 也觸發高亮——滑鼠在 3D 裡不好對準，點擊是備案 |
| 縮圖 | 有 | 無 |
| 搜尋高亮 | 有 | **無** |
| 邊的粗細 | 依 `count` 分三段 | 固定：`imports` 0.6、`contains` 0.3 |
| 邊上的內容 | `count > 1` 時把數字標在線上，`#6b7a94` 次要文字色 ＋ 底色小框 | 同樣的門檻，數字是掛在線**中點的文字精靈**（`linkPositionUpdate` 每次更新放回中點）。字高 3.5（比節點標籤的 3 大一級）、底色 `rgba(10,13,20,0.82)`、單一中性近白 `#e6ecf5`——**數字不依型別分色**，型別由線本身講完了 |
| 點邊 | 釘出細節框（見「細節框」） | 同左，另加 `linkHoverPrecision(6)` 加大判定範圍 |

**兩個畫布都常駐**，切換只改 `visibility`。原因見下方「兩個坑」。

以下的「排版」「互動」「縮圖」三節寫的都是 **2D** 的規格。

### 細節框

點一條邊，把它聚合掉的內容釘在點擊處：**哪些檔案 import 哪些檔案、各自 import 了什麼名字**。元件是 `components/DetailBox.tsx`，**兩個畫布共用同一個**。

| 規則 | 說明 |
|---|---|
| 開 | 點邊。`contains` 沒有細節，點了不開 |
| 關 | **框外任何地方按下**（背景、節點、另一條邊）。框內按下不關，才能選字複製 |
| 換 | 點另一條邊＝舊的關、新的開。因此**點同一條邊不是 toggle**，看起來像沒反應——關閉的方式是點別的地方 |
| 位置 | 釘在點擊當下的座標，鏡頭移動後不跟隨。貼到容器邊緣時往回收 |
| 內容 | 依「來源檔 → 目標檔 → **行號**」分組，標題列是 `build.py → models/__init__.py　行 16`，下一行是那一組的名字 |
| 出現 | 120ms 淡入 ＋ 微放大（`detail-in`，keyframes 在 `index.css`）。點另一條邊時元件不會重建，所以要把 `animation` 歸零再放回去逼它重播 |
| 外觀 | 亮邊 `palette.borderBright` ＋ 陰影——框浮在圖上，不是圖的一部分，要分得出前後層次 |

**關閉寫在 `DetailBox` 自己身上**（框外 `pointerdown` 就 `onClose`），所以兩個畫布都只需要「開」那一個 handler。監聽掛在 effect 裡：effect 在 commit 之後才跑，開啟它的那次點擊早已傳播完，不會一開就自己關掉。

行號放在標題列而不是跟在每個名字後面：同一個 `from x import a, b, c` 的名字共用一行，寫成 `a (16), b (16), c (16)` 是三次重複。分組把行號提到只出現一次；同一對檔案若在兩行各 import 一次，就自然分成兩組——那反而是資訊。

細節有兩個來源、同一個型別 `ImportDetail[]`：收合層讀後端的 `properties.sources`，檔案層由 `transform.ts` 自己聚合。**認識後端形狀的只有 `transform.ts`**，元件不碰。

### 型別編碼兩邊共用

3D 的顏色直接取自 `style.ts` 的 `palette`，尺寸另有一組（球體的體積單位與 2D 的像素不同）：`repo` 9、`directory` 6、`external_package` 4.5、`file` 3.5、`class` 3、`function` 2.2。`parse_error` 的節點在 3D 是**整顆變紅**，不是紅框——球體沒有邊框可用。

### 兩個坑

| 坑 | 症狀 | 解法 |
|---|---|---|
| **沒有資料就碰 d3** | 模擬還不存在，`d3ReheatSimulation()` 丟 `Cannot read properties of undefined (reading 'tick')`，那個例外**打斷整個 render loop**——之後再放資料也畫不出來，畫面一片空白且毫無線索 | 調間距的 effect 一定要等 `graph` 有值才執行 |
| **條件渲染切換畫布** | 3D 畫布被卸載重建一次就起不來 | 兩個都常駐、只切 `visibility`。**不能用 `display:none`**，那會讓畫布尺寸歸零，切回來是空白 |

### 空白畫面要說得出原因

3D 起不來時畫面就是一片黑，分不出是沒資料、容器尺寸 0、還是 WebGL 掛了。所以左上角常駐一列診斷字：`3D · WebGL ✓ · 1280×720 · 節點 71 邊 63`，初始化丟例外時把訊息直接印在畫面中央。

容器掛載當下可能還沒有尺寸，所以寬高靠 `ResizeObserver` 餵，不是只在建立時讀一次。

### 代價

bundle 從 656 kB 變成約 2 MB。**code splitting 還沒做**，列在 plan 4.2。

## 契約

`types.ts` 與後端 `app/models/` 逐欄對應：

| 後端 | 前端 |
|---|---|
| `NodeType` / `EdgeType`（`StrEnum`） | 字串 union，不是 TS `enum` |
| `datetime \| None` | `string \| null`（JSON 沒有 datetime，不會自動變 `Date`） |
| snake_case | 原樣保留，不轉 camelCase |

目前**手抄**，靠人工同步。已用後端的 `/openapi.json` 逐欄核對過一次，欄位名、兩個 enum 的值、`analyzed_at` 的型別全部一致。

改成從 OpenAPI 生成是 plan 1.7 的後續，屆時要與這份手抄版 diff 一次——diff 不為空代表某一邊錯了，最可能是後端漏宣告 `response_model`。

## 視覺編碼標準

**型別決定形狀、顏色與大小，三者一致。大小不隨內容量變化**——「看到更細的東西」交給日後的縮放顆粒度，不靠節點大小表達。

| 型別 | 形狀 | 顏色 | 尺寸 | 標籤 |
|---|---|---|---|---|
| `repo` | 六角形 | `#f5c451` 黃 | 46 | 20px |
| `directory` | 圓角方形 | `#7de2ff` 青 | 26 | 17px |
| `file` | 圓形 | `#5b6b8c` 灰藍 | 15 | 15px |
| `external_package` | 菱形 | `#f0883e` 橘 | 20 | 15px |
| `class` | 五邊形 | `#d97fb8` 粉 | 13 | 14px |
| `function` | 三角形 | `#9c8f7a` 暖灰 | 9 | 13px |

`class` 與 `function` **比 `file` 小**：它們住在檔案裡面。數量也是理由——本專案
25 個 class、213 個 function，function 畫太大整張圖就只剩函式。粉與暖灰是一片
冷色裡僅剩的空位，不與目錄的青、依賴的藍、強調的紫撞。

### 三種邊靠色相分，粗細另有用途

| 邊 | 顏色 | 寬 | 箭頭 | 為什麼 |
|---|---|---|---|---|
| `contains` | `#46705c` 灰綠 | 1.4 | 0.7 | 它是**骨架**，不是重點 |
| `defines` | `#7a6a8f` 灰紫 | 1.4 | 0.7 | 同樣是骨架，只是換成程式碼裡的包含 |
| `imports` | `#7aa2e3` 藍 | 1.4 | 1.1 | 這才是這個工具要回答的東西 |

**原本兩者都是藍色系、只差明暗，實際看還是分不太出來**，所以改用色相。

**兩種邊同寬是刻意的**：粗細專門表達「這條線代表幾筆」，一個視覺頻道只講一件事。主次改由顏色與箭頭大小承擔。

### 聚合的線會標數字，粗細分段

`count > 1` 的邊在線上標數字，**兩個畫布都有**（3D 是線中點的文字精靈）。只有重疊時才標，否則每條線都掛一個 `1`。

下面的粗細分段是 **2D 限定** —— 3D 的線寬目前只依型別固定，見「畫布」。

| `count` | 線寬 |
|---|---|
| `> 2` | 2 |
| `> 8` | 2.8 |
| `> 20` | 3.6 |

**分段而不是連續映射**：收到目錄層時權重可能上看數十，連續映射會出現巨帶。門檻也是照**收合後**的量級訂的——原本訂在 1 / 4 / 9，但目錄層有七成的邊都在那之上，等於每條線都「粗」，粗細就不帶訊息了。

### 圖例要列出所有畫得出來的型別

`Sidebar` 的「圖例」是**人看的窮舉清單**，不是程式跑的迴圈——所以「`type` 是資料不是結構」那條在這裡不適用：**新增一種節點或邊型別，圖例就一定要跟著加**。

漏掉的後果是使用者在畫布上看到一個沒見過的形狀，翻圖例找不到它是什麼。

目前列出六種節點（`repo` / `directory` / `file` / `class` / `function` / `external package`，由外到內排序）與三種邊。**節點的圖例連大小也照畫布**：三角形從 11×11 切出來、面積只剩一半，看起來就是比圓形小一號——function 在畫布上本來就是全場最小的。

**邊的圖例三條同寬**，理由同「三種邊靠色相分，粗細另有用途」：粗細在畫布上專門表達「代表幾筆」，圖例若自己用粗細講主次，就跟畫布對不起來了。

### 解析失敗只改邊框

`parse_error` 有值的節點加紅色（`#ff6b6b`）虛線邊框。**形狀與顏色仍歸型別管**——換形狀會讓人以為那是一種新型別，而不是「這個檔案沒解析成功」。

標籤一律置於節點右側，`text-margin-x: 9`，超過 `200px` 截斷，帶 3px 底色描邊以免與線糊在一起。

## 層級

**層級（看多細）與視圖（看哪種關係）是兩個不同的軸。** 層級決定節點收到哪一層，視圖決定留下哪種邊。

七個選項，送給後端的是一個 `level` 數字：

| 選項 | 送出的 `level` |
|---|---|
| 整個專案 | `0` |
| 第 1 – 5 層目錄 | `1` – `5` |
| 不收合（最細） | `null` |

**層級樹吃 `contains` ＋ `defines`**（plan 5.1），所以「最細」不再只到檔案為止——不收合會一路看到 class 與 function，而函式比它所在的檔案深一層。

**預設是第 3 層。** 哪一層好看**取決於專案的形狀**，不是固定的：codegraph 的程式碼埋在 `backend/app/…` 底下，所以第 3 層才開始有東西看；第 2 層會把整個 `backend/app` 收成一個點，內部依賴全變成節點上的計數。扁平的專案則會在第 1 層就分開。層數開到 5，讓人自己找甜蜜點。

**5.1 之後同一個數字代表的東西變了**（本專案實測）：

| `level` | 節點 | 內容 |
|---|---|---|
| 2 | 44 | 只有目錄與淺層檔案 |
| 3 | 228 | 深層檔案的函式收回檔案，但 `tests/` 這種淺層檔案的函式**還在**（它們本來就只有第 3 層深） |
| 4 | 311 | 幾乎全展開 |
| 不收合 | 323 | 全部 |

深度是深度——淺目錄裡的東西本來就比較早「見底」，這在只有檔案節點時就已經如此（`README.md` 在第 2 層就保留自己）。宣告加進來只是讓它更明顯。**甜蜜點因此從第 3 層往前移到第 2 層**，plan 4.2 的驗收基準要重訂。

### 外部套件是另一個開關

收到目錄層時外部套件反而會變成節點的大宗（10 個目錄對 15 個套件），所以它需要自己的模式，送 `externals`：

| 選項 | 送出的值 | 行為 |
|---|---|---|
| 每個套件一個節點 | `full` | 原樣照畫 |
| **合成一個，可展開（預設）** | `grouped` | 併成一個節點，名單留在 `properties.packages` |
| 隱藏 | `hidden` | 連碰到它的邊一起消失 |

### 收合在後端做

前端只送一個數字。**聚合是圖的運算，屬後端**——見「硬性規則」。換層級會重新向後端要一次，代價與切視圖相同。

後端收合時的兩個回填，前端拿得到但**還沒有地方顯示**（plan 4.3）：收進同一個節點的 imports 記在 `properties.internal_imports`，合併的套件名單在 `properties.packages`。

### 排版跟著層級走

`layoutFor(level)`：檔案層用「由左往右」，因為 `contains` 是樹、`breadthfirst` 適用；**收合過的一律用力導向**，因為有環、會交叉，樹狀排版分出來的層級沒有意義。切完之後仍可手動改排版。

## 視圖（目前停用）

三種，切換時**只換送給後端的 `edge_types`，不換元件**——這是 plan 2.7 的驗收點。

| 視圖 | `edge_types` |
|---|---|
| **全部（預設）** | 省略 |
| 目錄樹 | `["contains"]` |
| 依賴圖 | `["imports"]` |

**`Sidebar` 的 `SHOW_VIEWS = false`，這個選單目前不顯示**：收合之後 `contains` 表現成「你在哪一層」，那個軸自然消失了。程式碼與 `views.ts` 都留著，改回 `true` 就是收合方案之前的樣子。連帶地 `views.ts` 的 `viewLayout`（視圖 → 排版）**現在沒有呼叫端**，排版改由層級決定，見上。

**切視圖會重新向後端要一次。** 前端不自己篩邊——篩選是圖的運算，屬後端，見「硬性規則」。

### 節點不會因為篩邊而消失

後端的 `view()` / `only_edges()` 篩邊但保留全部節點，所以「依賴圖」視圖在檔案層仍有 63 個沒有任何 `imports` 邊的節點（目錄、測試檔、空的 `__init__.py`）浮在旁邊。目前照畫，見「未定之處」。

## 排版

| 選項 | 實作 |
|---|---|
| 由上往下 | `breadthfirst`，深度方向 ×1.8 |
| 由左往右 | `breadthfirst`，座標軸對調後深度方向 ×1.8 |
| 放射 | `breadthfirst` + `circle`，**不做深度拉伸**，否則圓被壓成橢圓 |
| 力導向 | `cose`，斥力 12000、理想邊長 90 |

深度方向單獨拉伸（`DEPTH_STRETCH = 1.8`）的理由：層與層之間的距離就是線的長度，跟同層之間該分開調。

### 間距不是 `spacingFactor`

**間距滑桿不重跑排版**，而是排完之後以整張圖的中心為支點等比例縮放座標。

| | 為什麼不用 `spacingFactor` |
|---|---|
| 效果不均勻 | 它在算位置時對某些距離取 `max(節點大小, …)`，外圈被節點自身尺寸卡住，怎麼調都不動，只有中心幾層有反應 |
| 會被 `fit` 抵銷 | 圖變大 → 自動對焦把鏡頭拉遠 → 螢幕上看起來沒變，甚至更擠 |
| 慢 | 每動一格就重跑一次帶動畫的排版，拖曳時會卡 |

改成幾何縮放之後三個問題一起解決：每條線等比例變長、鏡頭不動、可以邊拖邊看。

滑桿範圍 `0.8 – 5.0`，預設 `2.2`。

### 何時重新對焦（fit）

| 事件 | fit |
|---|---|
| 換資料 | 是 |
| 換排版方式 | 是（整張圖會大搬家） |
| 調間距 | **否**（會抵銷撐開的效果） |

### 初始畫面

fit 之後把倍率夾在 `0.8 – 1.1` 之間：

| 情況 | 處理 |
|---|---|
| 低於 `0.8`（節點多） | 拉回 `0.8` 並把畫面移到 `repo` 節點——全部塞進畫面通常小到看不清字，寧可**從根部開始看**，其餘用拖曳或縮圖去找 |
| 高於 `1.1`（節點少） | 壓回 `1.1`。**收合到目錄層只剩幾十個節點時**，fit 會把鏡頭拉得很近，所有東西大得誇張 |

| 行為 | 規格 |

## 硬性規則

| 規則 | 破了會怎樣 |
|---|---|
| **畫布實例放 ref，不放 state**（2D 與 3D 都是） | React 重新渲染會重建整張圖：2D 失去 pan／zoom 與選取，3D 失去鏡頭角度 |
| **元件不直接碰 API 型別**，一律經 `transform.ts` | 後端 schema 一改，所有元件都要跟著改 |
| **樣式常數只出現在 `style.ts`** | 調色要翻遍元件 |
| **前端不做圖運算** | 換圖資料庫時前端也要跟著改，後端那層抽象就白做了 |

## 自行決定的部分

以下沒有上位依據，是實作時定的，要推翻只需改對應的一兩個地方。

| 決定 | 理由 | 推翻的代價 |
|---|---|---|
| 邊 id 由前端編（`type:source->target`） | 後端的 `Edge` 沒有 id，但 Cytoscape 需要 | 改 `transform.ts` 與它的測試 |
| **平行邊在前端聚合成一條** | `from app.models import Edge, EdgeType, Node` 在後端是三筆事實三條邊（資料層不該先丟資訊），畫出來卻是三條完全重疊的線，看起來像一條特別濃的關係。實測 231 條 imports 邊聚合後剩 135 條，**42% 是重疊的** | 改 `transform.ts` 的 `aggregate()` |
| `INITIAL_MIN_ZOOM = 0.8` | 上百個節點全塞進畫面會小到看不清字 | 改一個常數 |
| `INITIAL_MAX_ZOOM = 1.1` | 收合到目錄層只剩幾十個節點時，fit 會把鏡頭拉得太近 | 改一個常數 |
| 3D 的節點尺寸另定一組 | 球體的體積單位與 2D 的像素不同，不能直接沿用 | 改 `Graph3D.tsx` 的 `SIZE` |
| 3D 的間距係數 `24 × spacing` | 同一支滑桿要在兩種畫布上感覺差不多 | 改 `Graph3D.tsx` 一個常數 |
| 3D 的邊標籤用單一近白、不依型別分色 | 數字講的是「量」，與型別正交——型別已由線的顏色表達，再分色只是多兩種色相 | 改 `Graph3D.tsx` 的 `LABEL_COLOR` / `LABEL_HEIGHT` / `LABEL_BACKGROUND` |
| 間距用幾何縮放取代 `spacingFactor` | 見上方「間距」 | 改 `GraphCanvas` 的 `rescale()` |
| 深度方向 ×1.8 | 線太短，節點擠成一團 | 改 `layouts.ts` 一個常數 |
| 背景三層動畫的參數 | 純視覺偏好 | 改 `index.css` |
