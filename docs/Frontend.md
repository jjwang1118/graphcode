# frontend 規格

前端的職責、資料流、視覺編碼、互動行為與硬性規則。

後端的實作決定見 [Backend.md](Backend.md)；檔案擺放見 [System_arch.md](System_arch.md)；進度見 [plan.md](plan.md)。

---

## 定位

| | |
|---|---|
| **做什麼** | 把後端回傳的 `{ nodes, edges, meta }` 畫成可探索的圖 |
| **不做什麼** | 不做任何圖的運算。篩選、循環偵測、鄰居查詢**全部由後端負責**——前端只換一個請求參數 |

「視圖 = 同一張圖的查詢條件」這條原則在前端的意思是：切換目錄樹／依賴圖不是換元件，是換 `edge_types` 這個欄位。

## 檔案與職責

| 檔案 | 負責 | 不該出現什麼 |
|---|---|---|
| `src/api/types.ts` | 與後端 pydantic 對應的型別 | 任何邏輯 |
| `src/api/client.ts` | `fetch` 封裝，唯一碰 HTTP 的地方 | 圖的知識 |
| `src/graph/transform.ts` | API 形狀 → Cytoscape elements、平行邊聚合 | React、DOM、cytoscape 的 import |
| `src/graph/style.ts` | 顏色、形狀、大小、狀態樣式 | 邏輯與資料 |
| `src/graph/layouts.ts` | 四種排版的參數 | 間距（見下方「間距」） |
| `src/graph/views.ts` | 三種視圖 → `edge_types` ＋ 預設排版 | 篩選的實作（那在後端） |
| `src/components/GraphCanvas.tsx` | Cytoscape 實例、互動、縮圖 | 樣式常數（都在 `style.ts`） |
| `src/components/Sidebar.tsx` | 控制項與圖例 | 對 cytoscape 的直接操作 |
| `src/App.tsx` | 狀態與版面 | 上述任何一項的細節 |
| `src/index.css` | 全域底色與背景動畫 | 元件樣式（元件用 inline style） |

`transform.ts` 刻意**不 import cytoscape**：它是純函式，測試不用載入繪圖引擎，也不必等畫布存在就能寫。

## 資料流

```
使用者輸入路徑
      │
      ▼
client.analyze({ path, edge_types? })   POST /api/analyze
      │  GraphDocument
      ▼
App 的 useState                          ← 唯一的資料來源
      │
      ▼
GraphCanvas ── transform.toElements() ──→ cytoscape 實例（ref）
```

React 只負責**餵資料**與**觸發排版**。Cytoscape 的實例不在 state 裡。

## 契約

`types.ts` 與後端 `app/models/` 逐欄對應：

| 後端 | 前端 |
|---|---|
| `NodeType` / `EdgeType`（`StrEnum`） | 字串 union，不是 TS `enum` |
| `datetime \| None` | `string \| null`（JSON 沒有 datetime，不會自動變 `Date`） |
| snake_case | 原樣保留，不轉 camelCase |

目前**手抄**，靠人工同步。已用後端的 `/openapi.json` 逐欄核對過一次，欄位名、兩個 enum 的值、`analyzed_at` 的型別全部一致。

改成從 OpenAPI 生成是 plan 1.7 的後續，屆時要與這份手抄版 diff 一次——diff 不為空代表某一邊錯了，最可能是後端漏宣告 `response_model`。

## 視覺編碼標準

**型別決定形狀、顏色與大小，三者一致。大小不隨內容量變化**——「看到更細的東西」交給日後的縮放顆粒度，不靠節點大小表達。

| 型別 | 形狀 | 顏色 | 尺寸 | 標籤 |
|---|---|---|---|---|
| `repo` | 六角形 | `#f5c451` 黃 | 60 | 20px |
| `directory` | 圓角方形 | `#7de2ff` 青 | 32 | 17px |
| `file` | 圓形 | `#5b6b8c` 灰藍 | 18 | 15px |
| `external_package` | 菱形 | `#f0883e` 橘 | 24 | 15px |

### 兩種邊靠亮度分，不靠色相

| 邊 | 顏色 | 寬 | 箭頭 | 為什麼 |
|---|---|---|---|---|
| `contains` | `#2c3d5c` 暗 | 1.2 | 0.7 | 它是**骨架**，不是重點 |
| `imports` | `#7aa2e3` 亮 | 2.2 | 1.1 | 這才是這個工具要回答的東西 |

再多一種色相（綠、橘都已被佔用）會讓畫面變彩虹，用亮度差表達主次比較安靜。

### 聚合的線會標數字

`count > 1` 的邊在線上標數字並加粗到 3。只有重疊時才標，否則每條線都掛一個 `1`。

### 解析失敗只改邊框

`parse_error` 有值的節點加紅色（`#ff6b6b`）虛線邊框。**形狀與顏色仍歸型別管**——換形狀會讓人以為那是一種新型別，而不是「這個檔案沒解析成功」。

標籤一律置於節點右側，`text-margin-x: 9`，超過 `200px` 截斷，帶 3px 底色描邊以免與線糊在一起。

### 色票

| 用途 | 值 |
|---|---|
| 背景 | `#0a0d14` |
| 面板 | `#11151f` |
| 分隔線 | `#1e2536` |
| 文字 / 次要文字 | `#c8d3e3` / `#6b7a94` |
| 強調（hover、選取） | `#a78bfa` 紫 |

### 狀態樣式

| 狀態 | 表現 |
|---|---|
| `.dim` | 透明度 0.12 |
| `node.hl` / `edge.hl` | 紫色邊框加粗／線變紫變粗 |
| `node.match` | 黃色邊框＋黃色標籤 |
| `:selected` | 紫色邊框 |

## 視圖

三種，切換時**只換送給後端的 `edge_types`，不換元件**——這是 plan 2.7 的驗收點。

| 視圖 | `edge_types` | 自動切換的排版 |
|---|---|---|
| **全部（預設）** | 省略 | 力導向 |
| 目錄樹 | `["contains"]` | 由左往右 |
| 依賴圖 | `["imports"]` | 力導向 |

排版跟著視圖走的理由：`contains` 是樹，`breadthfirst` 適用；`imports` 有環、會交叉，樹狀排版分出來的層級沒有意義。切完之後仍可手動改排版。

**切視圖會重新向後端要一次。** 前端不自己篩邊——篩選是圖的運算，屬後端，見「硬性規則」。代價是每次切換都重跑一次分析。

### 節點不會因為篩邊而消失

後端的 `view()` 篩邊但保留全部節點，所以「依賴圖」視圖裡仍有 63 個沒有任何 `imports` 邊的節點（目錄、測試檔、空的 `__init__.py`）浮在旁邊。目前照畫，見「未定之處」。

## 排版

| 選項 | 實作 |
|---|---|
| 由上往下 | `breadthfirst`，深度方向 ×1.8 |
| 由左往右 | `breadthfirst`，座標軸對調後深度方向 ×1.8 |
| 放射 | `breadthfirst` + `circle`，**不做深度拉伸**，否則圓被壓成橢圓 |
| 力導向 | `cose`，斥力 12000、理想邊長 90 |

深度方向單獨拉伸（`DEPTH_STRETCH = 1.8`）的理由：層與層之間的距離就是線的長度，跟同層之間該分開調。

### 間距不是 `spacingFactor`

**間距滑桿不重跑排版**，而是排完之後以整張圖的中心為支點等比例縮放座標。

| | 為什麼不用 `spacingFactor` |
|---|---|
| 效果不均勻 | 它在算位置時對某些距離取 `max(節點大小, …)`，外圈被節點自身尺寸卡住，怎麼調都不動，只有中心幾層有反應 |
| 會被 `fit` 抵銷 | 圖變大 → 自動對焦把鏡頭拉遠 → 螢幕上看起來沒變，甚至更擠 |
| 慢 | 每動一格就重跑一次帶動畫的排版，拖曳時會卡 |

改成幾何縮放之後三個問題一起解決：每條線等比例變長、鏡頭不動、可以邊拖邊看。

滑桿範圍 `0.8 – 5.0`，預設 `2.2`。

### 何時重新對焦（fit）

| 事件 | fit |
|---|---|
| 換資料 | 是 |
| 換排版方式 | 是（整張圖會大搬家） |
| 調間距 | **否**（會抵銷撐開的效果） |

### 初始畫面

fit 之後若倍率低於 `0.8`，改為固定 `0.8` 並把畫面移到 `repo` 節點——全部塞進畫面通常小到看不清字，寧可**從根部開始看**，其餘用拖曳或縮圖去找。

## 互動

| 行為 | 規格 |
|---|---|
| **拖曳** | 背景拖曳平移；游標 `grab` / `grabbing` |
| **縮放** | 滾輪（靈敏度 0.5）、範圍 `0.05 – 6`；左下角 ＋／－（每次 ×1.4，以畫面中心為支點）與 ⤢（重新塞進畫面） |
| **hover** | 該節點與相鄰的邊變紫發亮，其餘整張圖淡到 12%；移開後還原成搜尋當下的狀態 |
| **搜尋** | 對 `label` 做不分大小寫的子字串比對。**高亮而非篩選**：符合的變黃、其餘變暗，畫面自動移到第一個 |
| **節點拖動** | Cytoscape 內建，可單獨搬動節點 |

搜尋不做篩選的理由：篩掉之後看不出它在整棵樹的哪個位置，而那正是這個工具要回答的事。

### 縮圖

右下角 200×150 的第二個 Cytoscape 實例，**唯讀**（關閉縮放、平移、框選、拖動）。

| 機制 | 說明 |
|---|---|
| 內容 | 排版完成後複製主畫布算好的座標，不重算 |
| 樣式 | 無標籤、無箭頭、`haystack` 線，只留位置關係 |
| 視角框 | 由主畫布的 `extent()` 換算成縮圖座標，跟著 `viewport` 事件即時更新 |
| 點擊 | 主畫布平移到該位置（200ms 動畫） |

## 背景動態

三層純 CSS 疊加，**不進 Cytoscape 的繪圖迴圈**，所以節點數變多也不影響。

| 層 | 效果 | 週期 |
|---|---|---|
| `.bg-grid` | 44px 網格斜向漂移 | 26s |
| `.bg-glow` | 中央紫色輝光呼吸 | 9s |
| `.bg-scan` | 青色橫帶由上往下掃過 | 11s |

格線同時是**拖曳的參考物**：格線固定、節點移動，才看得出畫面有沒有在動。

`prefers-reduced-motion: reduce` 時三層動畫全部關閉。

## 硬性規則

| 規則 | 破了會怎樣 |
|---|---|
| **Cytoscape 實例放 ref，不放 state** | React 重新渲染會重建整張圖，pan／zoom 與選取全部消失 |
| **元件不直接碰 API 型別**，一律經 `transform.ts` | 後端 schema 一改，所有元件都要跟著改 |
| **樣式常數只出現在 `style.ts`** | 調色要翻遍元件 |
| **前端不做圖運算** | 換圖資料庫時前端也要跟著改，後端那層抽象就白做了 |

## 測試

| 對象 | 方式 |
|---|---|
| `transform.ts` | vitest，6 個測試：欄位對應、邊 id、平行邊不撞號、決定性、順序、空圖 |

## 自行決定的部分

以下沒有上位依據，是實作時定的，要推翻只需改對應的一兩個地方。

| 決定 | 理由 | 推翻的代價 |
|---|---|---|
| 邊 id 由前端編（`type:source->target`） | 後端的 `Edge` 沒有 id，但 Cytoscape 需要 | 改 `transform.ts` 與它的測試 |
| **平行邊在前端聚合成一條** | `from app.models import Edge, EdgeType, Node` 在後端是三筆事實三條邊（資料層不該先丟資訊），畫出來卻是三條完全重疊的線，看起來像一條特別濃的關係。實測 231 條 imports 邊聚合後剩 135 條，**42% 是重疊的** | 改 `transform.ts` 的 `aggregate()` |
| `INITIAL_MIN_ZOOM = 0.8` | 87 節點全塞進畫面會小到看不清字 | 改一個常數 |
| 間距用幾何縮放取代 `spacingFactor` | 見上方「間距」 | 改 `GraphCanvas` 的 `rescale()` |
| 深度方向 ×1.8 | 線太短，節點擠成一團 | 改 `layouts.ts` 一個常數 |
| 背景三層動畫的參數 | 純視覺偏好 | 改 `index.css` |

## 未定之處

| 項目 | 缺什麼 |
|---|---|
| **孤點** | 「依賴圖」視圖裡有 63 個節點一條邊都沒有，浮在旁邊佔位置。曾討論「藏起來 ＋ sidebar 顯示數量」，使用者選擇**先不做** |
| **超級節點** | 本專案 `app/models/__init__.py` 有 59 條入邊（佔 imports 的 26%），在畫面上是蜘蛛網中心。這是專案真實的結構，樣式解決不了，要靠分群或收合 |
| **縮放顆粒度（semantic zoom）** | 放大才出現檔名、縮小只剩資料夾。使用者明確說是「後日談」。會動到 `transform.ts` 與 `style.ts` |
| **目錄分群（compound node）** | 用巢狀方框取代 `contains` 線。最能解決「節點多了很亂」，但改變整個視覺隱喻，`transform.ts` 要多產 `parent` 欄位 |
| **hover 展開聚合的細節** | `transform.ts` 已經把每一筆的名字與行號存進 `data.detail`，但畫面上還沒有地方顯示 |
| **切視圖要重打一次分析** | 大 repo 會明顯卡。快取或改成一次拿全部再篩，都還沒決定 |
| **錯誤呈現** | 目前只在 sidebar 顯示一行紅字，沒有重試、沒有分類 |
| **上千節點的策略** | 預設收合、依目錄分群、邊聚合成帶權重的邊都還沒做 |
| **`client.ts` 的錯誤型別** | 只有一個 `ApiError`，沒有區分 400 與 500 |
