# ingest 規格

對應程式碼 `backend/app/ingest/`。職責的位置定義在 CLAUDE.md › 架構 › ingest。

目前只實作本機路徑這條路；zip 是階段 3。

---

## 1. 職責

輸入一個使用者給的路徑字串，輸出**一個可以安全走訪的根目錄**。

| 做 | 不做 |
|---|---|
| 檢查路徑落在允許清單內 | 走訪目錄、看檔案內容（scan 的事） |
| 交出一個 `Path` | 跳過 `.git` / `node_modules`（scan 的事，那是雜訊過濾不是安全） |
| — | 挑哪些副檔名去解析（parse 的事） |
| — | 判斷是不是一個合法的專案 |

後續階段一律只看到一個目錄，不知道 source 原本是什麼。**新增輸入方式（zip、git clone）只該動這一層。**

---

## 2. 介面

| 名稱 | 簽章 | 說明 |
|---|---|---|
| `allowed_roots_from_env` | `(env: Mapping[str, str] \| None = None) -> list[Path]` | 從環境變數組清單。`env` 為 `None` 時讀 `os.environ` |
| `from_local_path` | `(raw_path: str, allowed_roots: Sequence[Path]) -> Path` | 回傳根目錄；不被允許時丟 `IngestError` |
| `ALLOWED_ROOTS_ENV` | `str` = `"CODEGRAPH_ALLOWED_ROOTS"` | 環境變數名 |
| `IngestError` | `Exception` | 這一層唯一的例外型別 |

清單**以參數傳入**，`from_local_path` 不自己讀環境變數。讀環境變數是薄薄一層，由呼叫端組合。理由見 §8.2。

---

## 3. 行為

### 3.1 組允許清單 · `allowed_roots_from_env`

| # | 規則 |
|---|---|
| R1 | 以 `os.pathsep` 分隔（Linux 是 `:`）。 |
| R2 | 空白項一律忽略。 |
| R3 | 每一項都 `Path.resolve()` 之後才放進清單。 |
| R4 | 環境變數未設定或為空字串時回**空清單**。 |

### 3.2 檢查路徑 · `from_local_path`

依序執行，任何一步不通過就丟 `IngestError`：

| # | 規則 |
|---|---|
| R5 | 清單為空 → 拒絕。**未設定＝全部拒絕**，不是「沒有限制」。 |
| R6 | 把使用者給的路徑 `Path.resolve()`，算掉 `..`、跟到 symlink 的最終位置。 |
| R7 | 清單裡的每一項也 `resolve()` 之後才比對。 |
| R8 | 用 `Path.is_relative_to()` 按**目錄層級**比對，不得用 `str.startswith()`。 |
| R9 | 任一項通過即算通過。 |
| R10 | **通過 R9 之後**才檢查 `is_dir()`。順序不得對調，理由見 §8.1。 |

---

## 4. 產出的資料

一個 `Path`，已 `resolve()`，保證是存在的目錄且落在允許清單內。

---

## 5. 錯誤與邊界情況

全部以 `IngestError` 表達，**不回錯誤碼**——ingest 不認識 HTTP，狀態碼由 API 層決定。

| 情況 | 例外訊息（僅供日誌） |
|---|---|
| 環境變數未設定 | `CODEGRAPH_ALLOWED_ROOTS 未設定，本機路徑模式停用` |
| 路徑在清單外 | `路徑不在允許清單內：<絕對路徑>` |
| 路徑在清單內但不存在／不是目錄 | `路徑不存在或不是目錄：<絕對路徑>` |

> **例外訊息含絕對路徑，不可原樣回傳給前端。** 「`/etc` 不在允許清單 `/home/user/project` 內」等於把伺服器的目錄結構與清單內容送出去。詳細訊息只進日誌，對外只說路徑不被允許。API 層怎麼落實見 `api.md`。

### 三種繞過方式與對應規則

| 使用者給的路徑 | 為什麼騙得過字串比對 | 擋在哪 |
|---|---|---|
| `/allowed/../../etc` | 開頭確實是清單上的路徑 | R6，`resolve()` 先算掉 `..` |
| `/allowed_other` | 開頭字串對得上 `/allowed` | R8，按目錄層級比對 |
| `/allowed/link` → `/etc` | 字串完全合法，實際指向別處 | R6，`resolve()` 跟到最終位置 |

## 6. 不變式

| # | 保證 |
|---|---|
| I1 | 回傳的路徑必然是絕對路徑，且必然落在某個允許項之下。 |
| I2 | 清單為空時，**沒有任何輸入**能通過。 |
| I3 | 清單外的路徑一律只得到同一種錯誤，回應不因該路徑是否存在而不同。 |
| I4 | 本層不改動檔案系統，也不複製任何檔案。 |

I1 只涵蓋**入口那一個路徑**。清單內的資料夾裡若有 symlink 指向外部，走訪時仍會逃出去——那個洞由 scan 補（見 `scan.md` R3）。

## 8. 附錄：設計理由

### 8.1 為什麼先查清單、後查存在（R10）

反過來的話，錯誤訊息會變成一個**探測工具**：對清單外的路徑回「不存在」或「不是目錄」，等於告訴對方那個路徑存不存在。清單外的一律只回同一種錯誤。

### 8.2 為什麼清單以參數傳入

| 好處 | 說明 |
|---|---|
| 可測 | 測試直接餵一份假清單，不必 monkeypatch 環境變數（那種測試容易互相干擾） |
| 無全域可變狀態 | 與 CLAUDE.md 對語言 registry 的要求一致 |

### 8.3 為什麼未設定是「全部拒絕」（R5）

忘記設環境變數的後果必須是**功能不能用**，不能是整台機器開放。出錯要往關閉的方向倒。

### 8.4 命名

函式命名避開 `resolve`——那個字在本專案已是管線某一段的名字（名字 → 節點）。zip 那條路日後叫 `from_zip()`，兩者對稱。
